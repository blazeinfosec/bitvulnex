## What this run proves

- **The lab is alive.** A trainee can land, browse markets, sign up,
  log in, get a deposit address, get credited by an admin, place
  orders, cancel them, lend, file tickets, hit public APIs — every
  primary path works end-to-end against the running stack.
- **The mock-market feed is live.** Ticker chyron updates every 2s;
  book + chart + recent trades all stream via WS; market orders fill
  against the seeded depth from `mm.alpha` / `mm.beta`.
- **Admin operations work.** All five admin queues respond, user
  search finds seeded accounts, balance-adjust credits land
  immediately.
- **CTF players will indeed be able to use it.** The only friction
  point for fresh accounts is balance setup (D-3 — must admin-credit
  or do the deposit flow). Once funded, every feature trainees need
  to exercise the planted vulns is operational.

## Recommended follow-ups (not blocking)

1. **D-5: wire API key auth or hide the UI.** Currently keys are
   issued but useless. Pick one:
   - Implement `x-bvbe-api-key` header support in
     `apps/web/lib/auth.ts` and scope checks per route.
   - Or remove the create button from `/account/api-keys` until
     auth is wired.
2. **D-3: seed `whale1`/`whale2` with realistic balances** so the
   account names match expectation, or rename them to make it clear
   they're empty by default.
3. **N-2 in test plan: `/api/health` has no DO NOT DEPLOY field** —
   add one if monitoring tools may probe it.
4. **Plan polish:** the smoke runs surfaced several field-name
   mismatches between the test plan's assumed payloads and the
   actual route schemas (`destAddress`, `name`, `category`,
   URL-encoded pair). Plan has been updated; further runs will not
   trip on these.
