tier-1-basic: |
  A verifier picks the key by name and trusts whatever the token
  says about how to use it. Same lookup feeds both symmetric and
  asymmetric paths.
tier-2-verbose: |
  The legacy verifier loads a kid-named key file and hands the bytes
  to whichever crypto path the JWT header asks for. Public-key
  material is exposed via JWKS; sign an HMAC token using those
  bytes as the secret and the verifier will accept it.
